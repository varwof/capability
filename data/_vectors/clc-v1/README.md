# CLC-v1 conformance vectors

Machine-readable conformance vectors for **CLC-v1** (the minimal capability
decision language).  These are the single source of truth used by the three
independent implementations:

- Go: [`varwof/register`](https://github.com/varwof/register) → `cmd/vectors-run`, `go test ./semantics/`
- Python: [`varwof/aic-capability-demo`](https://github.com/varwof/aic-capability-demo) → `vectors-run.py`, `property_test.py`
- TypeScript: [`varwof/aic-capability-demo/ts`](https://github.com/varwof/aic-capability-demo/tree/main/ts) → `vectors-run.ts`, `property.ts` (Node, zero dependencies)

## Files

| File | Purpose |
|---|---|
| `vectors.json` | **120** vectors: `syntax` (9) / `entail` (47) / `intersect` (14) / `decide` (50) |
| `property-cases.json` | 1184 deterministic **P11** cases (narrowing + order independence), generated by `../../scripts/gen-property-cases.py` |
| `offline-vectors.json` | 12 OCMP reference cases (R2–R7, all 11 §3 reason codes); checked by `../../scripts/check-offline-vectors.py` |
| `vectors.schema.json` | JSON Schema for the vector file (note: `grant` may be `null` = no grant, or `{}` = empty grant — under rev CLC-1.3 the empty object is the same as absent, i.e. unconstrained §9.1; every vector carries a `clc_revision` and a `conformance_class`) |
| `clc-v1-ambiguities.md` | Resolution log for conflicts found while implementing |

## Running

```bash
# Go (from the register repository)
CLC_VECTORS=../capability/data/_vectors/clc-v1/vectors.json go run ./cmd/vectors-run/

# Python (from the aic-capability-demo repository)
CLC_VECTORS=../capability/data/_vectors/clc-v1/vectors.json python3 vectors-run.py

# P11 property — composition narrows only (both implementations run the same file)
#   Go:     CLC_PROPERTY_CASES=.../property-cases.json go test ./semantics/ -run TestIntersectionProperty -v
#   Python: CLC_PROPERTY_CASES=.../property-cases.json python3 property_test.py

# OCMP offline reference vectors: coverage + vocabulary gate (no evaluator yet)
python3 ../capability/scripts/check-offline-vectors.py
```

Both runners assert **verdict and the normative reason code** (the part before
the first `:` per CLC-v1 §9.2) and exit non-zero on any mismatch.

## Third-party run contract

A vector is a self-contained test case: `grant`, `request` and (for
`intersect`) `others`.  Two extra fields change how a runner must behave:

- **`clc_revision`** (every vector): the revision the vector's inputs declare.
  A runner whose declared revision is incompatible (§12.1 — different major,
  or a smaller minor) MUST resolve the vector to `deny` with
  `unsupported_language_revision` and not evaluate anything else.
- **`raw_params`** (optional, `entail`/`decide` only): raw JSON object text of
  the *request* params when a decoded map cannot carry the input — duplicate
  JSON keys, non-finite / over-precision numbers, large or over-deep payloads.
  A runner MUST validate it at the input boundary (§6.2.1) and short-circuit the
  vector to `deny(<code>)` when it is invalid, before any grant comparison.
- **`result_params` / `result_constraints`** (`intersect` only): assertions on
  the *merged* grant.  A runner that only compares the verdict is not conforming
  — those fields were declared by the corpus from the start but were unread
  until 2026-09-11, which is how a Go/Python divergence in the empty-`params`
  merge survived a "75/75 green" run.
- **`multi`** (rev CLC-1.3, `decide` only): when `true`, `grant` + `others`
  form the authorization grant SET and the runner MUST aggregate per §9.1:
  any covering-and-allowing grant authorizes (union), residual obligations
  union across covering-and-allowing grants (`allow_unresolved`), and when no
  grant allows the first covering grant's reason in canonical input order is
  returned.
- **zero-source intersection**: `"grant": null` with no `others` is the
  zero-source case of §7 rule 5 and MUST resolve to `deny("absent_source")`;
  the runner must not dereference the absent grant.

Third-party implementations may run the corpus with this file plus the spec
and their own semantics; verified parity on all **120** vectors (verdicts,
canonical reason codes, the `result_*` assertions, and the
`expect.unresolved` residual-obligation channel, including the
`allow_unresolved` verdict of rev CLC-1.3) plus the P11 property file is the
v1 conformance bar (§12, principles P12).

## Adding a vector

1. Add the case to `vectors.json` with `id`, `kind`, `spec_clause` (every vector
   MUST cite a clause that exists — a vector without normative text is
   incomplete, and a rule without a vector is incomplete),
   `clc_revision`, `conformance_class`, `expect` (`verdict` + `reason`) and a
   one-line `derivation`.
2. Validate against `vectors.schema.json`.
3. Run both runners; if they disagree with your expectation, decide explicitly
   whether the *spec* is ambiguous (record it in `clc-v1-ambiguities.md`) or the
   implementation is wrong — never adjust the vector to make a run pass.
